# Handoff Plan Template

Every plan is written for an executor with **zero context**. Assume competent at following instructions, weak at filling gaps.

Three properties: self-contained context, verification gates per step, hard boundaries and STOP conditions.

File naming: `plans/NNN-short-slug.md`

---

## Template

```markdown
# Plan NNN: <Imperative title>

> **Executor instructions**: Follow step by step. Run every verification command before proceeding. On STOP conditions, stop and report. Update status in `plans/README.md` when done (unless reviewer maintains index).
>
> **Drift check (run first)**: `git diff --stat <planned-at SHA>..HEAD -- <in-scope paths>`
> Mismatch with "Current state" excerpts → STOP.

## Status

- **Priority**: P1 | P2 | P3
- **Effort**: S | M | L
- **Risk**: LOW | MED | HIGH
- **Depends on**: plans/NNN-\*.md (or "none")
- **Category**: bug | security | perf | tests | tech-debt | migration | dx | docs | direction
- **Planned at**: commit `<short SHA>`, <YYYY-MM-DD>

## Why this matters

2–5 sentences on problem, cost, and what improves.

## Current state

- Files and roles with line ranges.
- Code excerpts as they exist today.
- Conventions with exemplar file reference.
- Relevant `AGENTS.md` / `docs/` constraints inlined.

## Commands you will need

| Purpose | Command                                                          | Expected on success |
| ------- | ---------------------------------------------------------------- | ------------------- |
| Tests   | `PYTEST_LOW_MEMORY=1 .venv/bin/pytest tests/unit/test_foo.py -q` | all pass            |

(Exact commands from recon — not guessed.)

## Suggested executor toolkit

- Invoke **codelookup** skill before any source edit.
- Run `.venv/bin/python .cursor/skills/codelookup/scripts/pre_check.py` and include blast-radius Mermaid in analysis.
- Cascade-update all dependents in the same change.

## Scope

**In scope**: list files
**Out of scope**: list files with reasons

## Git workflow

- Branch: `advisor/NNN-<slug>`
- Conventional commits matching repo style
- Do NOT push or open PR unless instructed

## Steps

### Step 1: <title>

Precise instructions with file/symbol references.

**Verify**: `<command>` → expected output

## Test plan

- New tests: file, cases, pattern to follow.
- Verification command.

## Done criteria

- [ ] All verification commands pass
- [ ] Codelookup blast radius addressed (dependents updated or explicitly unchanged with reason)
- [ ] No out-of-scope files modified
- [ ] `plans/README.md` status updated

## STOP conditions

- Current state excerpts don't match live code.
- Verification fails twice after reasonable fix.
- Fix requires out-of-scope files.
- Key assumption is false.

## Maintenance notes

What future changes interact with this; what reviewers should scrutinize; deferred follow-ups.
```


## Quality bar

- Executable with only the plan file and repo?
- Every verification is a command + expected result?
- Exact files/symbols in every step?
- STOP conditions specific to this plan?
- No secret values; Planned-at SHA filled in.
